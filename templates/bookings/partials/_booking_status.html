{% load wagtailcore_tags tz %} {% comment %} The payment-return status region. Included once by booking.html when `payment_return` is present (the visitor has just come back from Stripe), and returned as-is by the `bookings:booking_status` polling endpoint (`GET forms/booking/status//`) — same template, same `booking` variable, so a poll response can replace this element with itself. Context (apps.bookings.views.booking_status / booking.html): booking a bookings.Booking, or None if the reference in the URL didn't match any booking. When present: .status (BookingStatus — pending/confirmed/cancelled/completed), .reading (a readings.Reading snippet), .start_at (UTC), .display_timezone (the IANA zone shown when the visitor booked), .public_ref No-JS path: this region still renders correctly on the plain, non-htmx page load that follows Stripe's redirect back (BookingPage.get_context always resolves `payment_return` server-side from `?ref=`/`?result=` — see apps/bookings/availability.py:booking_panel_context). Without JS/htmx the "confirming" state simply doesn't self-update — the visitor reloads the page (or checks their email) to see it move to "confirmed"; with htmx, `hx-get`/`hx-trigger="every 2s"` below does that automatically while `booking.status` is still pending, and stops polling on its own once the swapped-in response no longer carries those attributes (this same template only includes them while still pending). {% endcomment %}
